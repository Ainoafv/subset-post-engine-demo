Post Engineering Engine — working demo for Subset

One slice of a Post Engineering Brain turned into an executable system: rules live in config, generation runs in stages, deterministic validators check every objectively testable rule, an independent evidence-grounded reviewer judges relevance and claims, and a regression suite shows what moves when a rule changes.

Live in your browser: the rule config, the validators and the regression suite — edit the rules or the post and everything re-checks. The generation stages and the reviewer verdicts are a recorded sample run (in production they're LLM calls with schema-constrained outputs).

2 · Information selection (stage 1)

3 · Generated post (stage 3)

Slots filled under the approved structure. Claims cite evidence as [E1]–[E4]. Edit it — break a rule and watch the validators.

4 · Deterministic validators

Checked in code, not by a model. This is where "99.99% construction compliance" comes from.

RuleResultDetail

5 · Independent reviewer (evidence-grounded)

A separate model that never saw the generation prompt. Every claim must map to evidence; anything unsupported is flagged. Scores are calibrated against expert-reviewed examples.

6 · Rules as versioned config

v1.3

Your team edits rules here — no code change. Try: set max_hook_words to 12, or add "leverage" to banned_words.

7 · Regression suite — what moved?

A gold set of approved posts and known-bad cases runs on every rule change. A rule edit that breaks an approved post, or lets a bad one through, shows up here before it ships.
